# 登録画面で、メールアドレスが登録済みかが分かることを受け入れる

新規登録で同じメールアドレスを送ると「このメールアドレスはすでに登録されています」と表示し、誰でもそのメールアドレスが登録済みかを調べられる。これを防ぐにはメールでの本人確認（確認メールのリンクを開いてから登録を終える）が要るが、課題の範囲外なので作らない。本人確認がないまま表示を「登録しました」などにぼかすと、本人が登録できない理由が分からなくなるため、表示は残す。登録画面で分かる以上、ログインだけで隠しても効果が薄いので、ログインの応答時間の差（未登録のときは `password_verify()` を呼ばないので速く返る）も直さない。

## Consequences

- ログインのエラー文は「メールアドレスかパスワードが違います」のまま、未登録とパスワード違いを分けない。分けても困る人はいないが、ログイン画面で登録済みかを教える理由もないため
- 登録済みかを本当に隠すなら、メールでの本人確認と、ログインで未登録のときもダミーのハッシュで `password_verify()` を呼ぶことを、まとめて入れる。片方だけでは隠せない
- 登録の二度押しで、パスワードが合えばログインさせる動き（`Controller_Auth::post_register`）は、この判断とは別。パスワードを知っている本人だけが通る
